# 原图在上、游戏图在下

默认交付上下直接拼接的对照PNG；同时保留独立游戏成图供下载。用户明确只要单图、只改图标或不需要对照时服从该次要求。对照只涉及交付排版，不改变场景的16:9生成要求。

1. 上方使用本次真正的用户场景原图，不用风格参考、人物参考、已有对照图或上一张生成图。连续修改复用最初场景原图；不可获得时只交单图并说明缺少原图，不伪造前后对照。
2. 下方使用已完成固定装备叠加、通过验收的最终游戏图。先完成场景/HUD，再拼接；不让图片模型生成整张对照图，也不重绘、调色或给上方添加HUD。
3. 上下区域同宽且严格等高，分割比例1:1，直接贴合，无默认标题、边框、分隔线或区域外留白。上方区域尺寸等于下方游戏图尺寸，背景填充纯黑色（RGB 0,0,0）；原照片按EXIF正向显示后，用contain方式等比缩放、完整居中适应，绝不拉伸或裁切。竖图通常左右黑底，较宽横图通常上下黑底；这些黑底只属于原图展示区域，不是生成场景的黑边。下图原尺寸粘贴，不缩放或裁掉HUD。原始文件保留，不覆盖。
4. 下方为16:9游戏图时，上下各占一个16:9区域，整个对照图固定8:9，例如1920×2160，无论原图是竖图、方图、宽幅或其他比例。原图也是16:9时自然铺满上方区域；其他比例完整居中，剩余区域保持黑色，不再让上半部分随原图比例变高。已认可非16:9游戏图的明确局部修改例外也保持上下等高，整体尺寸为游戏图宽度×两倍游戏图高度。

用Pillow只进行用户要求的确定性排版：

```bash
python <skill_root>/scripts/compose-comparison.py \
  --original /absolute/path/source-photo.jpg \
  --generated /absolute/path/final-gameplay.png \
  --output /absolute/path/photo-gameplay-comparison.png
```

新场景默认检查下图严格16:9。仅明确局部修改已认可的非16:9成图时可加`--preserve-canvas`；不能用这个开关掩盖新场景尺寸失败。脚本拒绝覆盖文件与非PNG输出。宿主规则要求保存文件时分别保存对照图及独立成图，并以对照图为主要预览；附独立成图链接即可，不必重复大幅展示。图片生成工具自动展示的中间结果不能替代最终对照图。

查看实际拼接结果：上下严格等高、照片完整居中、未覆盖区域纯黑，顺序正确、上图未被游戏化、下图像素/尺寸/HUD不变，无额外分隔留白或混入参考图。未执行脚本或未实际预览时不声称排版验证通过。
