# 固定装备资产与叠加

## 资产来源
来源：https://www.gtabase.com/gta-san-andreas/weapons/ ，下载日期2026-10-08。
`equipment-catalog.json`记录本页42枚装备图形的英文名、中文释义、类别、下载地址、尺寸和SHA-256；文件保存在`assets/gtabase-equipment/`，保留下载字节及透明底。GTABase是第三方资料站，不是Rockstar官方发布渠道；这些图标不是技能作者原创，也不声称获得开放再分发许可。工作流独立编写，来源声明保留。

本页图形包括自带黑色圆角边框的装备图和64像素的小型设备图。保留各自原貌：不裁掉绘制的边框、不重画、不改成统一白色、不拉伸、不做立体化。允许仅去除未绘制的透明外边距、等比缩放和透明合成；不是保证任何尺寸都与PS2实机像素一致。

## 按场景选择
下表是本工作流的选择规则，不是复制网页的攻略描述。完整名称及资产路径从JSON查；不要只写“枪”或“随机装备”，生成前选定一个具体ID。

| 情境 | 可选ID与处理 |
|---|---|
| 观景/拍照且双手可用 | `camera`；新增角色可持相机，原有抱物或操作不强改 |
| 花店/送花/约会 | `flowers`；原有动作优先 |
| 普通跑步/骑车/点单/抱物 | `fist`；通过scene-rules城市携行/遭遇分支可选枪，不能因为“跑步”退回拳头；点单/抱物和骑手动作不强改 |
| 用户选武装角色或合适城市携行/遭遇分支 | `pistol-9mm`、`silenced-pistol-9mm`、`desert-eagle`、`smg`、`m4`、`ak-47`等；同步决定携行/瞄准/射击，不能把所有持枪都当开火/通缉 |
| 用户选冲锋枪 | `micro-smg`、`smg`、`tec-9`；无型号时默认`smg`，不要混成一团泛化枪形 |
| 用户选霰弹枪/步枪 | `shotgun`、`sawn-off-shotgun`、`combat-shotgun`、`ak-47`、`m4`、`rifle`、`sniper-rifle`；匹配当前装备，不把乡村步枪、突击步枪和狙击枪当同一型号 |
| 球场/台球或明确工具情境 | `baseball-bat`、`golf-club`、`pool-cue`、`shovel`、`cane`；有相应动作或明确指定才选。原版机制不等于本工作流一定模拟挥打 |
| 明确涂鸦/灭火 | `spray-can`、`fire-extinguisher`；不能只因墙面或餐厅就添加 |
| 明确夜视/热成像/跳伞 | `night-vision`、`thermal-vision`、`parachute`；只有实际装备状态或明确要求时选，不因夜景就自动绿色全屏滤镜 |
| 明确其他特殊装备 | 从目录选择指虎、匕首、警棍、武士刀、电锯、重型武器、投掷物、遥控炸药/引爆器等；不纳入普通旅游的随机池，不由天空直升机推断主角有火箭筒 |

目录完整保留成人礼物道具`dildo`/`vibrator`，不用于默认旅行随机池；只有用户明确要求且适合画面时选。金额和装备可按筛选后候选调用`sample-state.py`，同张重试/局部修改锁定状态。旧参数`pistol`兼容映射至`pistol-9mm`；`rifle`明确指目录的乡村步枪。

通过scene-rules遭遇条件时可调用`sample-state.py --encounter`。输出的`action`、`reticle`、`muzzle_flash`与装备一起使用；默认在探索35、武装携行30、瞄准20、射击15的相对权重中选一次。这是工作流变化比例，不是游戏官方规则；传入显式候选时只抽适用类型。不能只取装备丢掉动作字段，也不在同张修正时重新抽。
没有对峙NPC但适合武装携行的城市探索，用`--armed-exploration`在探索60/携行40中抽，准星与枪口效果始终关闭；两种标志不能同时使用。

## 新图执行
1. 查看选定ID对应的原图，核对JSON中文名与实际装备。图标不传给模型要求重画；渲染参考仍按场景规则使用。
2. 图片工具生成场景、雷达和其他HUD，左装备槽保留连续背景，不画图标/边框/占位符。右上HUD共用一个矩形排版网格，不画外包框；装备线框左边与金额`$`的左边齐平，时钟/生命/护甲条共用右边界，金额行在这两个界限内排布。1920×1080基准外组`x=1605,y=34,w=270`，内部左对齐线建议`x=1613`，默认空槽`1605,34,108,96`；按`min(W/1920,H/1080)`缩放。弹药在槽下方且不侵入金额；不通过拉伸数字或图标凑矩形。
3. 取得本地成图后放大查看右上HUD，测量实际美元符号含描边的左缘像素X，传`--align-left X`；此数值不是按旧图猜“右移若干像素”。脚本用源图线框边缘作锚点，不在槽内居中，也不把伸出框的枪管当线框。空槽偏移/变窄时传实测`--box X Y WIDTH HEIGHT`；金额已认可就移图标，不移动金额。若槽内有旧图标先局部移除并恢复背景；若新的对齐位置超出原清空区域，先局部扩展该空区域。不能透明图盖旧图或用黑/白矩形掩盖。
4. 执行下方脚本，`--blank-slot-confirmed`表示执行者已经看图确认，不是要求用户再次批准。脚本只合成一枚源图，输出新PNG，尺寸和槽外像素不变。不对最终合成图再次用图片工具整体重绘，否则图标又会失真。
5. 查看最终游戏图：装备选择、源图边框/比例、HUD间距与清晰度正确；再按output-layout拼接默认对照图，保留独立游戏PNG并遵守宿主文件交付规则。不要把尚未叠加的中间图放入下半部分。

```bash
python <skill_root>/scripts/overlay-equipment.py \
  --input /absolute/path/generated-with-empty-slot.png \
  --output /absolute/path/final-with-equipment.png \
  --equipment camera --align-left 1613 --blank-slot-confirmed
```

示例1613只是排版基准，执行时必须换成实际测量值。源图抗锯齿和整数缩放使线框边缘允许约1像素视觉误差，不能以此放任明显错位。脚本需要Pillow；`--list`列全部ID。校验和/依赖失败停止合成，不回退自绘。环境不能取得本地图片或运行叠加时说明未完成，继续保留场景。

## 已有成图只换装备
先锁定原尺寸、人物、镜头、雷达、金额和其他HUD；测定装备槽及美元符号左缘。旧图标先局部清除并恢复背景，再以`--box`和`--align-left`叠加；空槽直接合成。不要为对齐移动已认可金额或重抽数字。
